# 基本概念与定义
Go语言中的通道(Channel)是goroutine之间通信的核心机制，而通道又分为有缓冲(Buffered)和无缓冲(Unbuffered)两种类型。
* `无缓冲通道`是通过 `make(chan T)`创建的通道，它没有数据存储能力，容量为0，这种通道要求发送和接收操作必须同时准备好才能完成数据传递，否则会阻塞当前goroutine
* `有缓冲通道`则是通过 `make(chan T, capacity)`创建的，其中capacity>0，这种通道具有固定的缓冲区，可以在被接收前存储一个或多个值。

## 阻塞行为差异
阻塞行为是两个通道最核心的区别
* 无缓冲通道：
    * 发送操作会被立即阻塞，直到另一个goroutine执行对应的接收操作
    * 接收操作会被立即阻塞，直到另一个goroutine执行对应的发送操作
    * 这种机制确保了严格的同步通信，发送和接收必须 `不见不散`
* 有缓冲通道：
    * 发送操作仅在缓冲区已满时阻塞
    * 接收操作仅在缓冲区为空时阻塞
    * 只要缓冲区未满/非空，操作就可以立即完成，实现异步通信（从某种角度上讲，借助 生产者 + 缓冲队列 + 消费者 去理解 ）

## 使用场景对比
* 无缓冲通道适用场景
    1. 需要严格同步：如协程之间的信号通知，任务协调
    2. 确保数据即时性：如实时控制信号传递
    3. 实现同步原语：如waitgroup、互斥锁等
    4. 握手式通信：要求发送和接收方必须同时就绪的场景
* 有缓冲通道适用场景
    1. 生产者和消费者速度不一致：缓冲可以起到类似mq消峰填谷 缓解处理速度差异
    2. 提高吞吐量：允许暂时堆积未处理的数据
    3. 批量处理数据：如日志手机、限流缓冲
    4. 解耦发送和接收操作
    5. 处理数据突发： 当然这个对于短时间内的突发流量，不能完全依赖缓冲通道，因为业务上能配置的缓冲通道capacity业有限

## 底层实现机制
两种通道都是使用`hchan`结构体实现，内部处理不同：
* 无缓冲通道：
    * 无缓冲时，发送和接收操作直接通过协程调度器的gopark和goready实现阻塞和唤醒
    * 数据直接从发送方内存复制到接收方内存，不经过缓冲区
    * 需要维护发送方`sendq`和接收方 `recvq`的等待队列
